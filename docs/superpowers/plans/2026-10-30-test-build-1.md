# hkg-climate-page Plan 2: test build 1 (page, app, panel patch, package)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A NEMESIS package the owner can install on the car that adds the climate page (layout B) to the right split screen, shows the real seat states and the outside temperature, and **logs** seat taps (`would set …`) without sending anything; uninstall restores the stock panel byte for byte.

**Architecture:** Our own app (`hkgclimate.app`, ordinary uid) does all the work: it reads seats from `BCMManager` and the outside temperature from `DATCManager`, runs the seat logic, keeps the split-screen page list, and serves a small hand-written binder protocol. A thin page class injected into the stock panel app (`RightScreenHome`) draws what the app sends and forwards taps. The panel gets two smali hooks (register page id 4 in `cM()`, return it from `aS(4)`), built off-car into a `classes.dex` whose bsdiff delta against the stock odex ships in the package; on the unit a vendored `lpatch` rebuilds the APK (streaming `zipadd`, new) and the install follows HMG Leafia Plus's system-app swap.

**Tech Stack:** Java 8 source compiled with JDK 17 against Android API 19 (`javac` + `d8` + `aapt` + `apksigner`, no Gradle), JUnit 4.13.2 for host tests, smali/baksmali 2.5.2, Python 3 (`bsdiff4` 1.3.1), C (freestanding ARM `lpatch`, clang + lld), mksh/toolbox shell for the package scripts, `qemu-arm` (Arch `qemu-user`) for host runs of the ARM binary.

**Spec:** `docs/superpowers/specs/2026-10-30-hkg-climate-page-design.md` (approved). Read with it: `docs/research/2026-10-30-split-screen.md` (panel hooks, page list) and `docs/notes/2026-10-30-status-and-findings.md` (seat values, outside temperature, install method).

## Global Constraints

- Target: 2023 US Ioniq 5, `ro.build.product` matching `NEEV23.USA.*.260507`. Anything else is refused with a message to update; the stock RightScreenHome must match its md5s (APK 161,884,916 B, odex 2,137,656 B).
- Vehicle commands only through the stock services. **This build sends no vehicle command at all**: it contains no reference to `com.hkmc.usm`; seat taps log `would set <method> <value>` (tag `HkgClimate`). Nothing is sent or logged as a command at boot or on a state update.
- Seat values (both seats): 2 off; 8/7/6 heat high/mid/low; 5/4/3 cool high/mid/low. Order off -> high -> mid -> low -> off. Option 6 = heat and cool fitted; any other option = heat only.
- Outside temperature: valid only when its state is `0xffff`, the value isn't `100000.0` and isn't `-40`. Display unit from `getTemperatureUnit()`: 1 = °C, 2 = °F, anything else = °F.
- Switch temperature default 60 °F.
- Page id 4 (CLIMATE), title string `0x7f0a0090`. Our page catches every Throwable at every entry point; a page that fails to load is simply absent.
- No manufacturer files, jars or decompiled code in the repo. Stock files live in `private/HKGCLIMATE/stock` and `~/code/LEAFIA/private/stock`; work trees in `private/work/` (git-ignored). Our stub classes declare only names we use, written by us.
- Anything written to `/system`: stock checksum gate, backup in `/data/nemesis/backup/hkg.climate.page/`, uninstall restores exact bytes.
- Package shell: mksh/toolbox, no `printf`, `tail`, `head`, `seq`, `[[ ]]`. Remount only via `nemesis remount rw|ro`.
- Names: NEMESIS id `hkg.climate.page`; Android package and Java root `hkgclimate` (`hkgclimate.core`, `.link`, `.app`, `.page`).
- Licence GPL-3.0. Files copied from HMG Leafia Plus keep their GPL header plus a line naming the source commit; credit in `NOTICE.md`.
- Commits: plain words, ending `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

2. **Outside temperature invalid** (state `0xff`/`0xfe`/`0`, value `100000.0` or `-40`): top line says unknown and taps heat. Test in Task 2.
