# hkg-climate-page Plan 5: presets (version 2, seats)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Up to four named presets, built in the settings app from the driver and passenger seat settings and applied with one tap on the climate page's preset slots.

**Architecture:**
- **Core (host-tested):** a `Preset` value, a `PresetList` (validation, order, text codec), and `ClimateCore.onPresetTap`. A preset tap sends each chosen seat's target value through the same `SeatCommander` (the `CheckedSeatSender`) that seat taps use.
- **App:** stores presets in its preferences, serves their names to the page, and adds a preset list and editor to settings.
- **Page:** the four slots become live buttons that send a new oneway `TX_PRESET`. The panel patch is rebuilt.

**Tech Stack:** as plans 2–4.

**Spec:** `docs/superpowers/specs/2026-10-30-hkg-climate-page-design.md` ("2. The settings app", "3. Presets"). The owner's request (2026-10-30): "a basic preset builder that has driver/passenger seat as selectable options". Design decisions stated to the owner on 2026-10-30: up to 4 presets, one per page slot; each seat set straight to its target; seats already at the target skipped; driver first; cool choices only with option 6; version 2.0.0.

## Global Constraints

- Only the approved command is sent: `setFrontSeatHeatDrvStep` / `setFrontSeatHeatAstStep`, values 2..8, through `CheckedSeatSender`. A preset target is one of 2..8, or "leave as is" (−1).
- A preset tap sends at most one command per seat: driver first, then passenger. It sends nothing for a seat that is set to "leave as is", already at its target, not ready, or in an unknown state, and nothing for a cool target on a seat whose option isn't 6. Nothing is retried, and nothing is sent except from a page tap.
- Preset names: 1–10 characters after trimming, with no tab or line break. At most 4 presets; at least one seat must be set.
- Seat choices in the editor, in this order: Leave as is, Off, Heat high, Heat mid, Heat low, Cool high, Cool mid, Cool low. The cool choices appear only when that seat's option is 6.
- The page shows the first 4 presets in order. Empty slots stay greyed and unclickable. Slot sizes are as plan 4 (180 × 50 dp, 24 dp gap).
- Panel safety unchanged: every page entry point catches Throwable, there is no com.hkmc reference, and page→app calls are oneway.
- Version `2.0.0` (versionCode 4).
- Commits: plain words, ending `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Preset tapped while one seat is already at its target:** only the other seat gets a command. Test in Task 1.
2. **Saved preset with a cool target, seat later reporting a non-6 option:** that seat is skipped, and no cool value is sent. Test in Task 1.
3. **Corrupt or hand-edited stored presets** (bad numbers, too many, long names): loading keeps the valid ones (at most 4) and never crashes. Test in Task 1.
4. **Presets changed in settings while the page shows them:** the page names update, and a tap on a slot whose preset was just deleted sends nothing. Test in Task 1 (index out of range) and Task 2.
5. **The same preset tap delivered twice:** one set of commands. Test in Task 1.

### Task 1: Core: presets and applying them

**Files:**
- Create: `core/src/hkgclimate/core/{Preset,PresetList}.java`
- Modify: `core/src/hkgclimate/core/{ClimateCore,PageState}.java`, `link/src/hkgclimate/link/PageLink.java`
- Test: `core/test/hkgclimate/core/{PresetListTest,ClimateCorePresetTest}.java`

**Interfaces:**
- Produces:
  - `final class Preset`:
    - fields `String name`, `int driver`, `int passenger` (each −1 or 2..8);
    - `static final int LEAVE = -1`;
    - `static String check(String name, int driver, int passenger)` returns null when valid, else a short reason ("name 1-10 characters", "choose at least one seat", "bad seat value");
    - `equals`/`hashCode`.
  - `final class PresetList`:
    - `MAX = 4`;
    - `static String encode(List<Preset>)` gives one line per preset, `name\tdriver\tpassenger`;
    - `static List<Preset> decode(String)` skips invalid lines, keeps at most `MAX`, and returns an empty list on null;
    - `static List<Preset> add/replace/remove/moveUp/moveDown(List<Preset>, …)` each return a new list, and add refuses beyond `MAX`.
  - `ClimateCore`:
    - `void setPresets(List<Preset>)` updates the page state;
    - `int onPresetTap(int index, long requestId)` returns the number of commands sent. It shares the existing `TapGate`, returns 0 for an index out of range or when not ready, and follows Global Constraints for each seat.
  - `PageState` gains `String[] presetNames` (length 4, null for an empty slot) and `boolean[] presetEnabled` (true when the slot has a preset and the seats are ready).
  - `PageLink`:
    - `TX_PRESET = IBinder.FIRST_CALL_TRANSACTION + 3` (in: int index, long requestId; sent `FLAG_ONEWAY`);
    - keys `K_PRESET_NAMES` (String[]) and `K_PRESET_ENABLED` (boolean[]).
