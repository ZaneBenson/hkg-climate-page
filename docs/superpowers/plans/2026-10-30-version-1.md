# hkg-climate-page Plan 4: version 1 (owner's layout changes, no approval flow)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Version 1 as the owner asked after test build 2 (2026-10-30). Seat taps always send the approved command. Each seat button's border shows what its next tap will do (orange heat, blue cool). The top line shows only the outside temperature. The seat buttons and preset slots are 10% smaller, so the right column no longer runs off the slot.

**Architecture:** The same three parts as before. The panel page changes, so the page dex, the panel delta and `package/patch/*` are rebuilt with the existing pipeline. The approval switch, the test-mode strip and the log-only commander are removed.

**Tech Stack:** as plans 2 and 3.

**Spec:** `docs/superpowers/specs/2026-10-30-hkg-climate-page-design.md`. The owner's changes in this plan override its version-1 layout notes (the "taps will heat/cool" top line, the test-mode strip, the approval switch); Task 4 updates the design to match. Seat command approval: `docs/notes/2026-10-30-status-and-findings.md`.

## Global Constraints

- Only the approved command is ever sent: `USMManager.setFrontSeatHeatDrvStep(int)` / `setFrontSeatHeatAstStep(int)`, values 2..8, one step per page tap. Nothing is sent at boot, on state updates, on settings changes, or as a retry. The `CheckedSeatSender` value gate and the `check-app.sh` usm checks stay.
- Taps send by default; there is no approval switch and no test mode.
- Sizes, in the page's dp units:
  - seat buttons 180 × 180 (were 200 × 200);
  - level bars 36 × 9 (were 40 × 10);
  - preset slots 180 × 50 (were 200 × 56);
  - the horizontal gap between buttons stays 24;
  - text sizes are unchanged.
- Seat button border: orange `#FF8A00` when the next tap heats, blue `#2D9CDB` when it cools, grey `#62797F` when the seat is unavailable. The level bars keep showing the current state (orange heat, blue cool, grey off).
- Top line: `Outside 65 °F`, or `Outside temperature unknown`. No "taps will …" text.
- Version `1.0.0` (versionCode 3) for the APK and NEMESIS.data.
- Panel safety unchanged: every page entry point catches Throwable, and the page references no `com.hkmc` code.
- Commits: plain words, ending `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Seat already on in the other mode:** the border shows the seat's current mode (the next tap steps within it), not the switch-temperature choice. Test in Task 1.
2. **Outside temperature unknown or invalid:** the border is orange (taps heat), and the top line says unknown. Test in Task 1.
3. **Seat state unknown (0, 9, −1) or seats not ready:** grey border, disabled button, and a tap sends nothing. Test in Task 1.
4. **A stale page or old app** (the Bundle has no tap-kind array): the page draws grey borders without crashing. Test in Task 3 (reading code; host check of the null path).
5. **Updating from test build 2:** the install no longer leaves a dead approval preference that could block sending. Taps send right after the update. Test in Task 2.
