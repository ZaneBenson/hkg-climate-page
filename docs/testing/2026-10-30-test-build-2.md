# Test build 2: on-car checklist

This build lets the seat buttons **change the seats**, but only after you turn on an
approval switch in the settings app. With the switch off it behaves like test build 1: taps
only write a line to a log. Each tap sends one step, using only the seat values we saw the
stock controls send on your car (off; heat high, mid, low; cool high, mid, low). Nothing is
sent at start-up, when the car's state changes, or when you change a setting. Please do the
steps in order and write down anything odd, even if it seems small. Package:
`dist/hkg-climate-page.zip`, or `dist/hkg-climate-usb.zip`, which puts the package and the kit
on one stick (see its `README-USB.txt`: the install runs on insert, the kit from NEMESIS
Manager's "Run USB NEMESIS.sh").

## Before you install

- Test build 1 is already on the car. You install this one over it (step 1).
- Only US firmware 260507 is supported. Anything else is refused with a message to update.
- The approval switch starts **off** after the update.
- Have the car on (ready to drive) for the seat tests. Seat heating and cooling will not work
  otherwise. If the car refuses a command (for example because it is not ready), a
  `no change after 3 s` message is expected, so please note whether the car was on.

## Steps

1. Put the new zip on the USB drive and install it with NEMESIS, like last time. NEMESIS
   uninstalls test build 1 first (the stock right-hand panel is put back), then installs the
   new build and restarts the unit. Keep the USB drive in until it says to remove it.
2. With approval **off**: the yellow "Test mode" strip shows on the climate page, and tapping
   a seat button changes nothing in the car.
3. Open the Climate Page settings (the **Settings** button on the page, or the app in the app
   list). Turn on **Send seat commands to the car** and confirm the question. Back on the
   page, the yellow strip should be gone.
4. With the car on (ready to drive):
   - First turn **both seats off** with the car's touch strip. Each tap on the page steps
     from the seat's current setting, so the taps below assume both seats start off.
   - In the settings, set the switch temperature to its highest, **85 °F** (about **29 °C**
     if the car shows Celsius), so taps heat. The page's top line should end in
     "taps will heat" (unless it is 85 °F or hotter outside).
   - Tap the **driver** button four times: heat high, mid, low, off.
   - Then tap the **passenger** button the same way.
   - Each tap should change the seat within about a second, and the page and the touch strip
     should agree with the seat.
5. Set the switch temperature to its lowest, **40 °F** (about **4 °C**), and read the page's
   top line again. Taps cool only when the outside temperature is at or above the switch
   temperature, so on a day colder than 40 °F the line still says "taps will heat" and taps
   would still heat. In that case skip this step and say so in your report. If it says
   "taps will cool", repeat step 4: cool high, mid, low, off, driver first and then passenger.
6. Turn approval **off** again in the settings. Taps change nothing again, and the yellow
   strip comes back.
7. Turn approval back **on** and confirm the question, then restart the head unit. After the
   restart the seats should not change by themselves, and the switch should still be on.
8. **If a tap does nothing, or the settings screen's "Seat command" line says
   `no change after 3 s` or `send failed`: stop, run the kit right away and send the
   `HKGCLIMATE` folder.** That means the stock seat service is not taking commands from our
   app, and the next step would be a different way of sending them. Do not keep tapping.
9. Run the hkg-climate kit right after testing (the kit only keeps about the last minute of
   the Android log) and send back the `HKGCLIMATE` folder. It includes the install log too.
   With the combined stick, open NEMESIS Manager and choose "Run USB NEMESIS.sh".
10. Optional: uninstall HKG Climate Page in NEMESIS and restart. The right-hand screen should
    work as it did before. Reboot once more afterwards.

## What we expect to see in the log

These lines are in the Android log (logcat), tag `HkgClimate`. The kit saves it as
`logcat-full.txt` in the `HKGCLIMATE` folder, and it covers only about the last minute. The
kit also copies `/data/nemesis/hkg.climate.page.log`, which is only the install and
uninstall log.

With approval on, every tap writes one line:

- `sent setFrontSeatHeatDrvStep <v>` for the driver seat
- `sent setFrontSeatHeatAstStep <v>` for the passenger seat

with `<v>` one of 2, 3, 4, 5, 6, 7, 8. With approval off, taps write
`would set setFrontSeatHeat…Step <v>` instead, as in test build 1.

How a refusal looks. The stock seat service hides its own errors: if it refuses our app, it
only writes an `E/USMManager` line ending in `RemoteException` to the log and then returns as
if all was well. So our app cannot tell directly. A refusal looks like this:

- `sent setFrontSeatHeat…Step <v>`, then about 3 seconds later
- `no change after 3 s: …` (the seat did not change), and the "Seat command" line on the
  settings screen shows the same `no change` text, and
- an `E/USMManager … RemoteException` line in the log around the same time.

`send failed …` is different: it only appears if our app cannot connect to the seat service
at all. Either one means: stop (step 8) and send the folder.

There should also be no `FATAL` line from `com.mobis.splitscreen.right` in `logcat-full.txt`.

## Things only the car can show

Please say yes or no to each:

- Was the car on (ready to drive) during the seat taps?
- Did each tap change the seat within about a second, for the driver and for the passenger?
- Did heat high, mid, low, off and cool high, mid, low, off come out in that order, and did
  the page and the touch strip agree with the seat? (Or was step 5 skipped because the page
  still said "taps will heat" at 40 °F?)
- Did the "Seat command" line on the settings screen ever say `no change after 3 s` or
  `send failed`?
- With approval off, did taps change nothing?
- After the restart with approval on, did the seats stay as they were, with the switch still
  on?
- Anything else odd (a blank or restarting right-hand screen, a second climate page, a shell
  error in `/data/nemesis/hkg.climate.page.log`)?

## If something goes wrong

- The right-hand screen goes blank or keeps restarting: uninstall HKG Climate Page in
  NEMESIS (it puts the original panel files back), then restart the unit.
- A message says the install failed and the panel was restored to stock: the car is back to
  normal, but uninstall HKG Climate Page in NEMESIS too, so it can be tried again cleanly.
- A message says the install could not be fully undone: do **not** restart the unit. Look at
  the NEMESIS log and tell us what it says.
- A seat does something you did not ask for: turn approval off in the settings, or uninstall
  HKG Climate Page in NEMESIS, and tell us exactly what happened.
